# Security

| No | Aspek Keamanan | Lokasi Pemeriksaan | Kondisi Sebelum | Kondisi Setelah Perbaikan |
|---:|---|---|---|---|
| 1 | **SQL Injection** | `buku/`, `anggota/`, `auth/`, serta file yang melakukan query database | Query database berpotensi menerima input pengguna secara langsung sehingga dapat dimanfaatkan untuk memanipulasi perintah SQL. | Seluruh query yang menerima input pengguna menggunakan **prepared statement** dengan parameter terikat. Pengujian menggunakan input `' OR '1'='1` tidak berhasil melewati proses autentikasi. |
| 2 | **Cross-Site Scripting (XSS)** | `buku/daftar-buku.php`, `buku/edit.php`, `anggota/daftar-anggota.php`, `anggota/edit.php`, dan tampilan data pengguna | Data yang berasal dari pengguna ditampilkan kembali ke halaman tanpa proses escaping yang konsisten. | Data yang ditampilkan telah melalui fungsi `e()` menggunakan `htmlspecialchars()` sehingga karakter HTML/script tidak dieksekusi oleh browser. Percobaan memasukkan `<script>alert('XSS')</script>` hanya ditampilkan sebagai teks. |
| 3 | **Cross-Site Request Forgery (CSRF)** | Form tambah, edit, hapus buku dan anggota serta form autentikasi | Request menggunakan metode `POST` belum memiliki mekanisme untuk memastikan request berasal dari halaman aplikasi yang sah. | Ditambahkan **CSRF token** melalui `includes/csrf.php`. Token dibuat dan disimpan pada session, kemudian diperiksa menggunakan `csrf_verify()` sebelum proses perubahan data dilakukan. |
| 4 | **Input Validation** | `buku/proses-tambah.php`, `buku/proses-edit.php`, `anggota/proses-tambah.php`, `anggota/proses-edit.php` | Validasi input sudah diterapkan pada beberapa bagian, tetapi beberapa nilai masih perlu diperiksa berdasarkan tipe dan format data yang diharapkan. | Ditambahkan validasi tipe data, pengecekan field wajib, serta validasi angka menggunakan `is_numeric()`. Nilai `id` juga dikonversi secara eksplisit menggunakan `(int)` sebelum digunakan. |
| 5 | **Session Security** | `auth/proses-login.php` dan `auth/logout.php` | Session pengguna belum diperbarui secara khusus setelah proses login berhasil sehingga berpotensi meningkatkan risiko session fixation. | Setelah `password_verify()` berhasil, aplikasi menjalankan `session_regenerate_id(true)` untuk menghasilkan session ID baru. Saat logout, session pengguna juga dihentikan dengan benar. |
| 7 | **Access Control** | Halaman `buku/`, `anggota/`, dan proses pengelolaan data | Pengguna yang belum login berpotensi mencoba membuka halaman pengelolaan secara langsung melalui URL. | Ditambahkan pemeriksaan autentikasi melalui `includes/auth.php`. Halaman yang membutuhkan login akan mengarahkan pengguna ke halaman login apabila session autentikasi tidak ditemukan. |
| 8 | **HTTP Method Validation** | File `proses-tambah.php`, `proses-edit.php`, dan `hapus.php` | Endpoint pemrosesan data perlu memastikan request menggunakan metode HTTP yang sesuai dengan fungsi yang dijalankan. | Setiap proses perubahan data memeriksa metode request, misalnya hanya menerima `POST` untuk tambah, edit, dan hapus. Request dengan metode yang tidak sesuai akan ditolak. |
